# Телефон: маска ввода и нормализация

Номер вводится в маске, на сервер уходит как есть, сервер приводит его к `+79XXXXXXXXX` и только так хранит. Показывается везде одинаково: `+7 930 111-22-33`. Поля и места показа в этом проекте — **[project.md](project.md)** рядом.

**Почему один формат хранения:** по номеру ищут человека, склеивают его заказы или брони, держат уникальность («одна заявка на номер»). Номер в другом виде — другой человек и дыра в ограничении.

## Маска — удобство, проверка — на сервере

- **Маска** — `static/js/phone-input.js`, подключена в обоих `base.html`. Держит вид `+7 9XX XXX-XX-XX`: «8» и «+7» в начале становятся «+7 », первой цифрой после кода может быть только 9, вставка «8 (930) 111-22-33» раскладывается в маску, правка в середине не уводит каретку в конец, Backspace до пустого очищает поле.
- Слушатели висят на `document`, а `htmx.onLoad` переформатирует значения из ответов — поля из HTMX-окон работают без повторной привязки. Своих `x-init`, `oninput`, `pattern` под телефон не пишем.
- **Сервер** не доверяет маске: без JS, из API или вставкой мимо неё придёт что угодно. Проверка и приведение — в схеме.

## Новое поле телефона

```html
<input class="input-field" id="phone" name="phone" type="tel" required maxlength="30" data-phone
       autocomplete="tel" inputmode="tel" placeholder="+7 900 000-00-00" value="{{ phone }}">
```

- `data-phone` включает маску; `inputmode="tel"` — цифровая клавиатура на телефоне; `autocomplete="tel"` — на сайте, в админке (чужие номера) не нужен.
- `maxlength="30"` с запасом: маска короче, но вставленный текст сначала попадает в поле целиком.
- Пустое поле — пустое значение: «+7 » маска подставит при фокусе и уберёт, если номер так и не начали. Значение с сервера можно отдавать хоть `+79301112233`, хоть отформатированным — маска покажет его в своём виде.
- **В схеме поле — тип `Phone`** из `schemas/public/v1/common.py` (`phone: Phone`, необязательное — `Phone | None`). Он приводит номер через `normalize_phone` и отвечает текстом `InvalidPhoneError`. Свой валидатор не пишем.
- Колонка в модели — `String(12)`, уникальность или поиск по номеру — индекс по нормализованному значению.

## Где что

| Что | Где |
|---|---|
| Приведение | `domain/contacts/phone.py`: `normalize_phone` (`«8 (930) …»` → `+79301112233`, иначе `InvalidPhoneError`) |
| Показ | `format_phone` → фильтр `phone_display`; `tel_href` → фильтр `tel` (`<a href="{{ phone|tel }}">`) |
| Поиск по части номера | `phone_search_digits`: «8 900 486» ищет то же, что «+7 900 486»; `None` — запрос не похож на номер, ищем по имени |
| Тип поля | `schemas/public/v1/common.py` — `Phone` |
| Маска | `static/js/phone-input.js` |

**Телефон организации** в контактах сайта (может быть городским) — не номер человека: это текст из настроек, маски нет, ссылка — фильтр `tel`, который принимает номер в любом виде.

## Скрипт общий для проектов на каркасе

`phone-input.js` одинаков во всех проектах. Правка поведения маски — здесь, в шаблоне, затем копия файла в проекты; расходиться им незачем.

## Проверка — в браузере

Набрать `89301112233`, вставить `+7 (930) 111-22-33`, исправить цифру в середине, стереть всё Backspace, открыть поле в HTMX-окне с уже сохранённым номером. Отправить без JS-маски (`curl`) номер в любом виде — сервер должен сохранить `+79…` или ответить ошибкой.
