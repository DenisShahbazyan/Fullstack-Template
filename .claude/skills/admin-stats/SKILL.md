# Статистика в админке

Страница отвечает владельцу на вопросы, после которых он что-то решает: растёт ли выручка, когда загрузка, кто возвращается. **Блок, после которого решать нечего, на страницу не ставим.**

## Слои

| Слой | Что делает |
|---|---|
| `crud/admin/stats.py` | Сырые счётчики и суммы за отрезок дат: `GROUP BY` в базе, не циклом в Python. Возвращает Pydantic-схемы из `schemas/admin/v1/stats.py` |
| `domain/stats/` | Расчёт без БД: периоды (`periods.py`), доли, проценты изменения (`change_percent`), загрузка. Сюда — тест, если считаются деньги |
| `web/admin/stats_view.py` | Собирает контекст страницы: зовёт crud за текущий и предыдущий период, форматирует числа, проценты, подписи и уровни цвета. Шаблон получает готовые строки |
| `web/admin/stats_period.py` | Выбор периода: `choose_period` из query, подпись, ссылки «‹ ›», плитки месяцев, кварталов и лет для окошка |
| `web/admin/pages/stats.py` | Роут ≤ 15 строк: `choose_period(local_today(), …)` → `stats_context(...)` → `render` |

Роутер — `web_require_admin`: выручка и клиенты — данные владельца, модератору не нужны.

## Период и сравнение

`app/domain/stats/periods.py`:

- `PeriodKind` — `month`, `quarter`, `year`; query: `?period=month&date=2026-10-01`, свой диапазон — `?start=…&end=…` (диапазон важнее вида периода).
- `calendar_period(day, kind, today)` — **данные в прошлом** (продажи, заказы): текущий период идёт по сегодня и сравнивается с тем же отрезком прошлого (1–25 октября с 1–25 сентября), прошедший — целиком с предыдущим целиком. Будущий не выбрать.
- **Данные лежат и в будущем** (брони, записи): период не обрезается сегодняшним днём — сравнение целиком с предыдущим целиком, будущие месяцы выбрать можно. Правка — в `calendar_period` проекта, а не второй функцией рядом.
- `range_period(first, last)` — свой диапазон: целые месяцы сравниваются с теми же целыми месяцами перед ними, остальное — с тем же числом дней.
- «Сегодня» — только `local_today()` из `core/clock.py`, границы дня в запросе — по местным часам: иначе вечерние заказы уедут в завтра.

Выбор периода на странице: стрелки к соседнему периоду, кнопка с подписью открывает окошко `picker-pop picker-pop--period` с плитками `picker-chip` (`is-on` — выбранный, `is-current` — текущий, `is-disabled` — будущий), свой диапазон — макрос `date_range` из `public/macros/date_picker.html` (с `max` = сегодня для данных в прошлом). Под заголовком итогов — даты сравнения текстом («сравниваем с 01.09 – 25.09.2026»).

## Блок страницы

- Заголовок со значком «?» — `help_popover` из `public/macros/help.html`. В пояснении: **что показано, как считается** (что исключено, с чем сравнивается) и **что с этим делать** («упала выручка при прежнем среднем чеке — стало меньше заказов: смотрите загрузку»).
- Изменение к прошлому периоду — процент с знаком и цветом; `None` из `change_percent` — «не с чем сравнить», а не 0 %.
- Деньги — фильтр `money`, проценты и доли считает Python.
- **Тепловая таблица** (загрузка по часам и дням недели) — `table.heat-table`, клетка `td.heat-cell` со `style="--heat: 0.42"` (доля от самой загруженной, 0…1) и `is-dark` при насыщенном фоне. Уровень и флаг считает `stats_view.py`, не шаблон.

## Данные — снимки, а не живые связи

Статистика прошлого не должна меняться, когда переименовали раздел, удалили товар или поменяли цену. Считаем по снимкам, записанным в момент события (название, раздел, цена, количество в строке заказа), а не через `item_id → Item → Category`. Новое измерение отчёта — сначала снимком в записи события, потом отчёт; для прошлых записей его не будет, и это честно.

Отменённое и тестовое в итоги не входит — фильтр в crud, одним местом, и строка об этом в пояснении блока.

## Проверка

В браузере: переключить месяц, квартал, год, стрелки, свой диапазон; текущий период сравнивается с тем же отрезком прошлого; пояснение «?» открывается на телефоне снизу; пустой период показывает «нет данных», а не ошибку.
