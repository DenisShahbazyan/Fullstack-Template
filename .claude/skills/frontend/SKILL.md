# Фронтенд: HTMX, окна, вёрстка

## Правка видна сразу, без перезагрузки

**Изменил данные через HTMX — обнови на странице всё, что их показывает:** шапку, счётчики, таблицы, списки выбора в других формах.

- Правленый блок — обычный swap (`hx-target`). Остальные — **out-of-band** (`hx-swap-oob`) в том же ответе, без отдельных запросов.
- Если зависимых блоков на странице много — один partial-сборщик oob-блоков страницы, который роут включает флагами. Новый зависимый блок = новый флаг там же, а не своя досылка в роуте.
- Досылаемый блок живёт в **отдельном partial** с `{% if oob %} hx-swap-oob="outerHTML"{% endif %}`, разметка не дублируется. Контекст собирает общая функция, а не копия в роутах.
- **Досылать можно только то, что есть на странице**, иначе `oobErrorNoTarget`. Тот же роут с другой страницы не досылает чужие блоки.
- **Partial, который сам включает сборщик oob-блоков, нельзя досылать через этот же сборщик** — шаблоны зациклятся. Досылаемую часть выносим в отдельный partial.
- Добавляя форму, спроси: **где ещё на странице видны данные, которые она меняет?** Каждое такое место обновляется в ответе.
- Проверка — в браузере: правка → всё зависимое обновилось без перезагрузки.

Не применимо: обычный POST без JS (отвечает редиректом), чужие правки (websocket и поллинг — YAGNI), переход на другую страницу после действия (редирект, не oob).

## Окна и ответы

- **Ответ на действие в окне** — пустое тело (окно закрывается) + oob-блоки + тост. Элементы внутри формы с `hx-target` на окно наследуют цель — у вложенных `hx-get` цель указывается явно.
- **Обычная форма** после успеха — `redirect` / `redirect_with_toast` (`web/toasts.py`), иначе F5 отправит её снова. Ошибку ввода показываем той же страницей с введёнными данными и `toast_context(...)`.
- **Ошибка в HTMX-запросе** приходит тостом: `web/errors.py` отвечает 200 с пустым телом и `HX-Trigger`, чтобы не затереть блок.

## Никаких браузерных диалогов

`alert()`, `confirm()`, `prompt()` и `hx-confirm` запрещены и на сайте, и в админке (ловит pre-commit-хук `scripts/checks/no_browser_dialogs.sh`).

- **Подтверждение** — макрос `confirm_dialog` из `templates/public/macros/modal.html`: `x-data="{ confirming: false }"` на обёртке, кнопка `type="button"` открывает окно, подтверждение — submit формы. Закрытие по Escape и клику по подложке.
- **Итог действия** — тост (`static/js/toasts.js`): `window.toast(...)`, `HX-Trigger` из ответа (`attach_toast`) или `?toast=` после редиректа.

## Стек и вёрстка

- **HTMX** — всё, что требует данных с сервера; эндпоинт возвращает HTML-фрагмент, не JSON. Никаких ручных `fetch` + `innerHTML`. Исключение — загрузка файлов: общий `gallery-upload.js` шлёт XHR ради прогресса и вставляет ответ через `htmx.swap` (скилл `uploads`, «Галерея в браузере»).
- **Alpine** — только локальная интерактивность (открыть/закрыть, табы); серверное состояние не дублирует.
- **Tailwind v4** — классы в шаблонах, без `style="..."` (исключение — динамические значения из данных, CSS-переменными). Цвета — только токены из `@theme` в `tailwind/input.css`. Повторяющийся ≥ 3 раз блок — компонент в `@layer components` (`btn`, `btn-danger`, `modal-*`, …) или макрос.
- HTMX и Alpine — локально в `static/js/`, не с CDN. Статика подключается с `?v={{ static_version('...') }}`.
- Новые классы появятся после `make css` (или `make css-watch`); бинарь — `make tailwind`, Node в проекте нет. В Docker CSS собирается при сборке образа.
- HTMX-фрагменты — роуты в `web/<side>/partials/`, шаблоны в `templates/<side>/partials/`. Логика в шаблоне — только `{% if %}`/`{% for %}`.
