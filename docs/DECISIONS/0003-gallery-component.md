# ADR 0003. Галерея с загрузкой: один компонент во всех проектах

Дата: 2026-10-26. Статус: принято.

## Контекст

В проектах на каркасе фото загружают в десяток форм, и в каждой загрузчик свой: в mix-cafe — одна общая полоса на всю пачку и SortableJS, в SENO — свой скрипт на каждую форму, в bathhouse — плитка на каждый файл с прогрессом поверх превью, звёздочка обложки, перетаскивание с призраком за курсором. Удачным оказался вариант bathhouse: видно, что именно грузится и сколько осталось, файл встаёт в галерею на место своей плитки, обложка не прыгает под рукой. Вариантов должно остаться не пять, а один.

## Решение

**Общий компонент галереи — те же правила, что у модуля загрузок (ADR 0002): правится только в шаблоне и копируется в проекты как есть.**

- **Файлы:** `static/js/gallery-upload.js` (очередь, плитка на файл, ужатие фото в браузере), `static/js/gallery-draft.js` (обложка и удаление в черновике), `static/js/drag-sort.js` (порядок перетаскиванием), `tailwind/gallery.css` (подключается `@import` из `input.css`), макросы `templates/public/macros/gallery_upload.html`.
- **Файл — отдельным запросом** (`POST`, поле `file`) XHR, а не `hx-post`: htmx не даёт прогресса по каждому файлу. Ответ — HTML, как у любого HTMX-роута: его вставляет `htmx.swap` (с oob-блоками), ошибка приходит тостом в `HX-Trigger` и встаёт текстом на плитку.
- **Два режима.** Запись есть — каждое действие сразу на сервере, ответ — перерисованная галерея. Записи нет (черновик) — файлы во временной папке, ответ — плитка; порядок и обложка — поля формы, запись принимает ключи через `claim_uploads`.
- **Обложка отмечается на месте**: плитки не переезжают, обложка первой встанет после обновления страницы.
- **Фото ужимается в браузере** до 2560 px, если оно больше этого или тяжелее 2 МБ: сервер всё равно перекодирует его в WebP, а с телефона по медленной связи лишние мегабайты — минуты. GIF и документы уходят как есть; что браузер не прочитал — тоже, решает сервер.
- **Перетаскивание — Pointer Events** (на телефоне — долгим нажатием), атрибуты `data-drag-sort` / `data-drag-id`, чтобы не пересечься со старыми `data-sortable` проектов. Без адреса в `data-drag-sort` порядок живёт только в форме.
- **Проектное расширение** — `galleryUpload.register(...)`: свой загрузчик для типа, который формой на сервер не отправить (видео частями прямо в S3 в bathhouse).

## Отвергнутые варианты

- **SortableJS.** Готовая библиотека, но 40 КБ ради одного жеста, а в bathhouse уже есть 150 строк, которые делают то же самое на телефоне и мыши.
- **Пачка файлов одним запросом.** Проще роут, но прогресс — один на всех, и ошибка в одном файле роняет всю пачку.
- **Плитки собирает JS по JSON-ответу.** Разметка плитки разъехалась бы с серверной: две копии вместо одного макроса.
- **Скрипты только на страницах с галереей.** Меньше байт на остальных страницах, но каждую новую форму легко оставить без скрипта; файлы маленькие и кэшируются.

## Последствия

- Новая форма с фото — макросы и три роута по контракту (загрузка, порядок, обложка и удаление), а не свой JS.
- Роут загрузки принимает **один** файл в поле `file`; несколько файлов — несколько запросов. Лимиты Caddy на число загрузок считают файлы, а не пачки.
- Правка компонента — в шаблоне, затем копия в каждый проект и проверка в браузере: в каждом проекте — своя страница с галереей.
