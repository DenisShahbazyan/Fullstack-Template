# Подключение к продовой БД из DBeaver

Postgres на сервере слушает `127.0.0.1:5432` — только loopback, из интернета порт закрыт. Подключение идёт по SSH-туннелю: DBeaver сам его поднимает, отдельный терминал не нужен.

## Почему так, а не открытым портом

`ports: "5432:5432"` без префикса публикует порт на всех интерфейсах, и Docker при этом пишет правило напрямую в iptables — **минуя ufw**. То есть база доступна снаружи даже при включённом файрволле, а `ufw status` этого не покажет. Нестандартный номер порта от сканеров не спасает: их перебирают целиком.

Префикс `127.0.0.1:` в [docker-compose.yml](../../../docker-compose.yml) оставляет порт виден только с самого сервера. Снаружи в него попадают через SSH, который и так открыт и защищён ключом.

## Настройки

### Вкладка Main

| Поле | Значение |
| --- | --- |
| Host | `localhost` |
| Port | `5432` |
| Database | `POSTGRES_DB` из `.env.docker` |
| Username | `DB__USERNAME` из `.env.docker` |
| Password | `DB__PASSWORD` из `.env.docker` |

`localhost` здесь — адрес **со стороны сервера**, уже внутри туннеля. Не IP сервера: до него DBeaver дойдёт по SSH, это настраивается на соседней вкладке.

### Вкладка SSH

Включить «Use SSH Tunnel».

| Поле | Значение |
| --- | --- |
| Host/IP | IP сервера |
| Port | `22` |
| User Name | SSH-пользователь |
| Authentication Method | Public Key |
| Private Key | путь к приватному ключу |
| Local Port | `0` (автовыбор) |

## Local Port и локальный Postgres

Если на рабочей машине уже поднят свой Postgres на 5432, `Local Port` **обязательно** оставить `0` — DBeaver возьмёт свободный порт сам.

Занятый порт даёт один из двух исходов, и второй хуже: либо ошибка «address already in use», либо молчаливое подключение к локальной базе вместо прода. Выглядит это как «данные с прода пропали».

Два поля с портами легко перепутать:

| Поле | Значение | Чей порт |
| --- | --- | --- |
| Main → Port | `5432` | сервера, внутри туннеля |
| SSH → Local Port | `0` | рабочей машины, снаружи туннеля |

`5432` на вкладке Main остаётся в любом случае — локальный Postgres на это значение не влияет.

## Проверка, что подключились к проду

```sql
select inet_server_addr(), current_database(), count(*) from users;
```

На проде `inet_server_addr()` вернёт адрес из docker-сети (`172.x.x.x`), локально — `127.0.0.1` или пусто.

Подключения стоит назвать по-разному («SЭNO prod (ssh)» и «SЭNO local»): перепутанное соединение на проде — самая частая причина случайного `UPDATE` не там.

## Если не подключается

**`authentication method 10 not supported` / ошибка про scram-sha-256** — старый JDBC-драйвер. Postgres 18 по умолчанию требует `scram-sha-256`; обновить DBeaver или сам драйвер в настройках подключения.

**`Connection refused` при рабочем SSH** — контейнер не поднят или порт не проброшен. На сервере:

```bash
docker compose --env-file .env.docker ps
```

У `postgres` в колонке PORTS должно быть `127.0.0.1:5432->5432/tcp`.

**Туннель поднимается, база не отвечает** — проверить, что Postgres жив:

```bash
docker exec postgres pg_isready
```

## Проверка, что порт закрыт снаружи

Запускать **с рабочей машины**, не с сервера:

```bash
nc -vz <ip-сервера> 5432    # ожидаем: Connection refused / timeout
nc -vz <ip-сервера> 16872   # старый порт, тоже должен молчать
```

Любой `succeeded` означает, что база доступна из интернета — разбираться сразу.
